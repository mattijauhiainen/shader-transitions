Cubic Hermite Interpolation

A textbook walkthrough of the math behind evalCurve: how four numbers (two values and two slopes) are turned into a smooth curve, and why the basis polynomials look the way they do.

1. The problem

We have a list of keyframes — pairs (t, v) — and we want a smooth function f(t) that passes through every keyframe. "Smooth" specifically means: no kinks (the slope is continuous across keyframes) and the curve does not wiggle wildly between keys.

Linear interpolation is the simplest answer:

It hits every key, but the slope jumps abruptly at each one. For a camera animation that's visible as a sudden change in angular velocity — the camera looks "twitchy." We need something that interpolates the value and the slope at each keyframe.

2. The Hermite idea: specify value and slope at both ends

Take a single segment between two keyframes. We will demand four things of it:

  1. At the left end, the curve has value p0.
  2. At the right end, the curve has value p1.
  3. At the left end, the curve has slope m0.
  4. At the right end, the curve has slope m1.

Four conditions means four unknowns. The next section turns those four conditions into four equations and solves them.

3. Working on the unit interval

Real keyframes can be anywhere on the timeline, with arbitrary spacing. To keep the algebra clean, we first solve the problem on the unit interval s ∈ [0, 1] and then map back. Define

s = (t − t₀) / (t₁ − t₀)

so s = 0 at the left keyframe and s = 1 at the right.

What does "look for a function" mean?

We don't know yet what f looks like. The strategy is to pick a family of candidate functions controlled by some unknown numbers, and then solve for the unknowns that make our four conditions hold. Concretely:

  1. Pick a template — a formula with placeholder constants in it.
  2. Plug in the four conditions; each one becomes an equation in those constants.
  3. Solve the system. The values that pop out give us our specific function.

For this to work, the template must have at least four free constants (one per condition) — otherwise we'd be over-constrained and the system would have no solution. It also helps if it has exactly four, so the answer is unique. And we'd like the template to be cheap to evaluate, smooth, and well-behaved.

Why a polynomial?

A degree-n polynomial has the form

a₀ + a₁·s + a₂·s² + … + an·sn

which gives us exactly n + 1 tunable knobs. Since we have four conditions, n = 3 — a cubic — gives us exactly four. Polynomials also tick every other box: cheap to evaluate (just multiplies and adds), smooth everywhere, and the four conditions turn into linear equations in the unknowns, so the solve is mechanical and always has a unique answer.

So the template we pick is the general cubic:

f(s) = a + b·s + c·s² + d·s³

with four placeholders a, b, c, d. (The letters are just names for "the four numbers we will solve for.")

Could we use a different family?

Yes — and people sometimes do. Any family with four free parameters could in principle satisfy four conditions. For instance:

  • a + b·s + c·sin(πs) + d·cos(πs) — a trig blend.
  • a + b·s + c·es + d·e−s — exponentials.
  • Rational functions, B-splines, custom easing curves, etc.

Each one would give a different curve shape and a different "personality" to the interpolation. But polynomials win in practice because:

  • The resulting equations are linear in the coefficients, so solving is trivial.
  • A cubic is the lowest-degree polynomial with enough knobs — anything higher (quartic, quintic) has spare freedom we'd have to invent extra rules to pin down.
  • Hardware can evaluate them in a handful of FMA instructions.
  • They reproduce simple behaviors exactly: a cubic Hermite with the right tangents reproduces a straight line; a quintic Hermite can also reproduce a parabola; etc.

Bézier curves and Catmull-Rom splines, by the way, are also cubic polynomials — they just expose different four parameters (control points instead of values + tangents). Any cubic can be written in any of these bases; they're all the same family viewed through different windows.

Solving the system

Imposing the four conditions on f(s) = a + b·s + c·s² + d·s³:

conditionatrequires
f(0) = p₀s = 0a = p₀
f(1) = p₁s = 1a + b + c + d = p₁
f'(0) = m₀s = 0b = m₀
f'(1) = m₁s = 1b + 2c + 3d = m₁

Two equations give a and b directly. Subtracting and combining the other two, we get

c = 3(p₁ − p₀) − 2m₀ − m₁
d = 2(p₀ − p₁) + m₀ + m₁

Substituting back into f(s) = a + bs + cs² + ds³ and grouping by which input each term multiplies:

f(s) = (2s³ − 3s² + 1)·p₀ + (s³ − 2s² + s)·m₀ + (−2s³ + 3s² )·p₁ + (s³ − s² )·m₁

Those four polynomials are the Hermite basis functions. They are exactly the four coefficients you see in the code:

(2 * s3 - 3 * s2 + 1) * k0.v   // h₀₀(s) · p₀
(s3 - 2 * s2 + s)      * m0    // h₁₀(s) · m₀  (then scaled by dt — see §6)
(-2 * s3 + 3 * s2)     * k1.v  // h₀₁(s) · p₁
(s3 - s2)              * m1    // h₁₁(s) · m₁  (also scaled by dt)

4. Reading the basis functions

Each basis function is a cubic that "owns" one of the four inputs. To see what role it plays, evaluate each one at s = 0 and s = 1, and similarly each one's derivative:

basis formula at s=0 at s=1 slope at s=0 slope at s=1
h₀₀2s³ − 3s² + 11000
h₁₀s³ − 2s² + s 0010
h₀₁−2s³ + 3s² 0100
h₁₁s³ − s² 0001

This table is the whole point. Each basis is "1" for exactly one of (left value, left slope, right value, right slope) and "0" for the other three. So when we add them up weighted by p₀, m₀, p₁, m₁, every condition is satisfied automatically, by construction.

6. Why tangents get scaled by dt

The Hermite basis we just derived assumes s ∈ [0, 1]. But our keyframes are spaced in real time t, with possibly unequal gaps. Going from "slope with respect to s" to "slope with respect to t" requires the chain rule:

df/ds = (df/dt) · (dt/ds) = (df/dt) · dt

where dt = t₁ − t₀ is the segment length. So if we want the curve's real slope at the left keyframe to be m₀ (in v-per-second), we have to feed the unit-interval formula a slope of m₀ · dt. That's why the code reads

(s3 - 2 * s2 + s) * m0 * dt
(s3 - s2)         * m1 * dt

The * dt is a units-conversion factor, nothing more. Without it, longer segments would look "lazier" than short ones — the geometry would silently depend on how you spaced your keyframes.

7. Choosing the tangents: Catmull-Rom

The Hermite formulation lets us pick any slopes we like at each keyframe. But the user only supplies values in the keyframe table — no slopes. We have to invent reasonable slopes automatically. The classic choice, used in this code, is the Catmull-Rom rule: at each interior keyframe, set the tangent to the average slope of the two adjacent segments.

mi = ½ · ( (vi − vi−1) / (ti − ti−1) + (vi+1 − vi) / (ti+1 − ti) )

Why average? It's the cheapest rule that's symmetric (treats left and right neighbours equally) and reproduces a straight line exactly: if three keyframes are colinear, the averaged slope is the line's slope, so the resulting Hermite segment is the line itself.

8. Endpoint and flat-span handling

Two cases need special treatment:

Endpoints. The first and last keyframes have no neighbour on one side, so there's no second chord to average with. The code returns 0 for the tangent at endpoints. Geometrically, the curve enters the first keyframe and leaves the last keyframe horizontally — it "eases in" and "eases out" of the whole animation.

Flat spans. If two consecutive keyframes have the same value (the user is intentionally holding a value steady), naïve averaging at the boundary keyframe between a flat segment and a sloped one would still produce a non-zero tangent — and a cubic with non-zero tangent against a flat target will overshoot before settling. The code defends against this:

if (slopeLeft === 0 || slopeRight === 0) return 0;

If either neighbouring segment is flat, the tangent is forced to zero, so a "hold" really holds, and the curve enters/leaves the hold smoothly without bouncing.

9. Putting it together — what evalCurve actually does

  1. If t is outside the keyframe range, clamp to the nearest endpoint value (no extrapolation).
  2. Find the segment [ki, ki+1] containing t.
  3. Compute the unit-interval parameter s = (t − ti) / dt and its powers s², s³.
  4. Look up tangents m₀ and m₁ from the Catmull-Rom rule (with endpoint and flat-span overrides).
  5. Combine value bases (h₀₀, h₀₁) with raw values, and tangent bases (h₁₀, h₁₁) with tangents scaled by dt: 
    return (2*s³ − 3*s² + 1) · v₀
     + (s³  − 2*s² + s) · m₀ · dt
     + (−2*s³ + 3*s²)   · v₁
     + (s³  − s²)       · m₁ · dt;

That's the whole algorithm. Every line in evalCurve traces back to one of three things: the four conditions of Section 2 (which fix the basis functions), the chain rule of Section 6 (which puts the dt on the tangents), or the Catmull-Rom and flat-span rules of Sections 7 and 8 (which choose the tangents on the user's behalf).
